⚡ AWS CloudWatch Embedded Metric Format (EMF) Log Stream

WasmPulse emits native EMF JSON logs to systemd journal / CloudWatch on every invocation. AWS CloudWatch automatically extracts high-resolution metrics without custom agents.

🛠️ Managing WasmPulse from AWS Console (Manual Guide)
Follow these exact steps in the AWS Management Console to operate your serverless engine in production.
1
EC2 Security Group Configuration
Allow inbound traffic to the WasmPulse HTTP gateway.

AWS Console Path:
EC2 > Instances > [Your Instance] > Security > Security Groups

Click Edit inbound rules and add:
Type: Custom TCP Port range: 8080 Source: 0.0.0.0/0 (or your corporate CIDR) Description: WasmPulse HTTP Gateway
2
Attach CloudWatch IAM Role
Grant your EC2 instance permissions to stream logs and metrics to CloudWatch.

AWS Console Path:
1. Open IAM > Roles > Create role > AWS service: EC2.
2. Attach policy: CloudWatchAgentServerPolicy.
3. Name role: WasmPulse-CloudWatch-Role.
4. In EC2 Console: Actions > Security > Modify IAM role > select WasmPulse-CloudWatch-Role > Update IAM role.
3
View Live Metrics in CloudWatch
Monitor microsecond cold starts and fuel consumption in real time.

AWS Console Path:
CloudWatch > Metrics > All metrics

Under Custom Namespaces, click WasmPulse/ServerlessEngine. Select dimensions:
  • TenantId, FunctionName: Per-function cold start & fuel
  • TenantId: Aggregate tenant invocations
4
Create CloudWatch Alarms & SNS
Trigger automated alerts if execution latency exceeds SLA limits.

AWS Console Path:
CloudWatch > Alarms > Create alarm

Metric: TotalLatencyUs > 5,000 µs (5 milliseconds).
Action: Send notification to SNS topic WasmPulse-Alerts (delivers instant email to engineers).
